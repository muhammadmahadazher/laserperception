# LaserPerception v0.2.0 release notes

Release date: 2026-08-20

LaserPerception v0.2.0 adds raw single-sweep ROS 2 LiDAR ingestion with time-aware TF-based
multi-sweep reconstruction in front of the unchanged PointPillars/TensorRT detector. It remains
pre-1.0 research software: LaserPerception did not train PointPillars, and this release is not a
production-readiness or safety claim.

## What changed since v0.1.0

v0.1.0 required callers to publish an already model-ready `PointCloud2` containing `x`, `y`, `z`,
and `time_lag`. v0.2.0 also accepts compatible single-sweep `PointCloud2` with scalar float32 XYZ,
provided a valid time-aware TF tree is available. The new boundary reconstructs current plus up to
ten historical acquisitions and publishes the same model-ready contract consumed by the existing
detector.

The lightweight Python wheel remains independent of ROS, CUDA, TensorRT, and OpenMMLab. nuScenes,
the pretrained checkpoint, ONNX, TensorRT engine, and GPU/ROS environment remain external.

## Raw ROS ingestion architecture

```text
Existing model-ready path (v0.1-compatible):
model-ready PointCloud2 (x, y, z, time_lag)
    -> exact_fast
    -> TensorRT FP16 PointPillars
    -> Detection3DArray

Raw ingestion path (new in v0.2):
single-sweep PointCloud2 (x, y, z) + time-aware TF
    -> bounded current + up to 10 historical sweeps
    -> same model-ready PointCloud2
    -> same exact_fast
    -> same TensorRT FP16 PointPillars
    -> same Detection3DArray
```

The raw path feeds the unchanged model-ready detector boundary. It does not alter the detector,
voxelization geometry, postprocessing, thresholds, class mapping, or output contract.

## Transform bug chronology

The first full-history W1 raw ROS attempt failed: it produced 354,184 points where the accepted
oracle produced 354,182. The discrepancy was localized to the transform adapter.

For the conventional ROS column-vector transform:

```text
p_target = R @ p_source + t
```

the pinned `SweepTransform` storage convention requires:

```text
rotation = R.T
translation = -R.T @ t
```

The initial adapter stored `-t`. A fail-first rotation-plus-translation regression exposed the
error; the minimal repair restored byte-exact W1 output and removed the prior range-membership
mismatch. The original failure, transform ledger, and repair evidence remain separately preserved:

- original failure SHA256: `d912eaa94cdb38ee1c8b6c6f4fc59831c31f37d33152b23d1d2a9f334a2fc8d6`;
- transform ledger SHA256: `0363fd23ff426aca7a9d88518203062a8e7440b0155a49879f639b3c96c18f2d`; and
- repair evidence SHA256: `078ceb041bf0123cc82b0e2ca1c97e6f47cf081eaa702254564f9c13150e2a66`.

## What did not change

v0.2.0 does not change the official pretrained PointPillars model, checkpoint, ONNX, TensorRT FP16
engine, `exact_fast`, MMDeploy postprocessing, thresholds, class mapping, voxel geometry, or
historical M1/M2/M3/M4.5 evidence. It adds no detector, training, optimization, custom CUDA, INT8,
tracking, camera fusion, localization, odometry, calibration automation, or vendor driver.

## Performance scope

M4.5/M4.5b was correctness and integration work, not a new throughput measurement. v0.2.0 has no
new canonical performance campaign and does not claim a measured raw-ingestion rate.

Historical v0.1/M3 evidence on the model-ready path found 10 Hz was the highest tested clean
sustained rate for representative full-history W1 in one RTX 4060 Laptop/WSL2 environment; 15 Hz
and 20 Hz were not sustained. Those results must not be interpreted as M4.5b raw-ingestion
throughput or as portable hardware guarantees.

## Limitations

The raw boundary accepts compatible ROS 2 `PointCloud2` containing scalar float32 XYZ only when a
valid time-aware TF tree is supplied. Extra fields are ignored by the frozen detector path.

This release does not provide or prove automatic sensor calibration, localization, odometry,
per-point intra-scan deskew, arbitrary vendor-driver integration, physical-sensor detection
accuracy, training/fine-tuning, tracking, camera fusion, INT8, Jetson validation, or safety
certification. The detector remains the official pretrained PointPillars nuScenes model; no claim
is made that arbitrary physical LiDAR distributions will achieve useful accuracy.

## Reproducibility and evidence

Correctness claims are semantic/software evidence intended to be reproducible when the pinned
stack and inputs are reproduced. Performance claims remain historical measurements from one
NVIDIA GeForce RTX 4060 Laptop GPU under WSL2, not portable capability guarantees.

Start with the canonical M4.5b record linked above and the
[benchmark map](../BENCHMARKS.md). No dataset points, checkpoint, ONNX, engine, private paths, or
GPU environment are distributed in the release.

## Upgrade notes from v0.1.0

Existing model-ready publishers can continue unchanged. To adopt raw ingestion, publish compatible
scalar float32 XYZ to `/laserperception/points_raw`, provide the documented fixed/time-aware TF
history, and run `laserperception_multisweep_builder` before the existing detector. Do not remove
`time_lag` from direct model-ready messages; the detector contract itself is unchanged.
