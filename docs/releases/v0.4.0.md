# LaserPerception v0.4.0 release notes

Release date: 2026-09-22

v0.4.0 expands LaserPerception from its historical PointPillars deployment path into a broader,
CPU-first perception platform. It packages reviewed engineering merged since v0.3.0 while
preserving all historical detector evidence and the separate frozen M8 execution identity.

## What changed since v0.3.0

### Perception platform APIs

P0 and P1 add immutable model manifests, a registry, exact input contracts, compatibility
validation, deterministic dry-run planning, and guarded PointPillars/DSVT backend construction.
Metadata inspection stays CPU-safe and does not discover optional hardware.

### CPU tracking

P2 adds deterministic class-aware multi-object tracking over explicitly timestamped,
precomputed `DetectionFrame` values. The tracker uses a constant XY velocity model and explicit
lifecycle rules. This release does not claim an end-to-end detector/tracker benchmark.

### Semantic result and evaluation infrastructure

P3 adds immutable row-aligned semantic results, taxonomy and coordinate descriptions,
identity-bound sidecars, and CPU confusion/IoU evaluation. No production segmentation model is
included.

### Data-adapter discovery

P4 adds metadata-first discovery and local inspection for eight reviewed input paths, reusing
canonical readers and documenting exact feature, temporal, calibration, coordinate, and dependency
boundaries.

### External workers and reproducibility

Provider-neutral worker tools verify artifacts, plan tasks, qualify external environments, persist
evidence, and keep scientific authorization separate. Local development remains CPU-first; heavy
frameworks and artifacts remain outside the wheel.

### M8 DSVT engineering readiness

The DSVT-Pillar + TransFusion candidate, frozen S1 protocol, input receipt workflow, external
qualification, and fail-closed execution evidence are documented. PRs #41–#45 improved Stage R
receipt handling, frame-major replay, full live pre-inference revalidation, and preservation of
failures before source load, gate completion, or backend construction.

M8 primary A2/E2 remains pending. A prior external primary attempt ended incomplete after 779
attempted conditions and contributed zero accepted canonical calls. The future campaign remains
bound to commit `6994d72c3e7691a86116d1417ac3ae08256d163f` and receipt file SHA256
`bef4c55575581aefe8f477e32d1b394f40823a0b0858c66c3ac5c1fae141ec4d`; this release does not
rebind it.

### Independent OmniLink evaluation

The repository documents an external OmniLink/OmniSim evaluation of v0.3.0. It independently
verified the multi-sweep transform/reconstruction convention and preserved a negative domain-gap
result: neither the sparse nor denser authored case produced a valid intended traffic-cone match at
score threshold 0.25. It is not a LaserPerception-run or dataset-level benchmark.

## What is not included

- No accepted M8 primary A2/E2 result.
- No zero-intensity, S2, DSVT training, or fine-tuning.
- No DSVT TensorRT end-to-end parity or production deployment claim.
- No production segmentation model.
- No new ROS throughput measurement.
- No physical-LiDAR or autonomous-driving safety claim.

## Upgrade and reproducibility notes

The core Python and ROS package versions are 0.4.0. Existing model ID
`pointpillars-nuscenes-v0.3` remains unchanged because it names a frozen model identity rather
than the package version. Historical v0.1.0–v0.3.0 release notes and evidence remain unchanged.

The wheel stays lightweight and excludes datasets, checkpoints, engines, private Drive state, and
external raw evaluation material. The v0.4.0 release note is excluded from the sdist, alongside the
historical v0.3.0 hash-bearing note, to preserve a non-circular artifact-hash process. Final wheel,
sdist, and checksum identities are published with the GitHub release built from the reviewed tag.
